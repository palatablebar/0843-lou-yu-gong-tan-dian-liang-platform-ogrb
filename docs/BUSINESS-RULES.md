# 业务规则

## 使用者

物业能源核算员使用本工作台处理公摊面积分摊与总表守恒。

## 主规则

房间用量按表计差读取整，楼宇总表减去分表得到公摊，再按面积分摊并守恒到瓦时。

计算以整数最小单位或十进制定点数为准，避免二进制浮点在边界上漂移。无法完成前置校验的行进入隔离区；跨行规则在计算后标记阻断或人工复核。

## 判定

- `PASS`：业务结果在允许范围内。
- `REVIEW`：数据可计算，但需要人工确认或存在轻微偏离。
- `REJECT`：存在来源、守恒、方向或上限阻断，不能签发。

## 批次

同一来源重复执行得到同一批次数值。签发要求阻断项为零，并携带当前版本号；旧版本提交会被拒绝。证据只在签发后生成。

## 共用泵电（两栋一台泵）

两栋楼共用一台水泵，泵表可能接在其中一栋（宿主楼）的总表底下。泵电只由接线记录 `*.wiring.json` 中登记的实际受益房间承担，未登记房间不分摊泵电。

口径（一律以整数瓦时 Wh 计算，最大余数法分摊，分摊之和严格等于泵表读数差）：

1. 泵表电量 = 止码 − 起码，换算为 Wh。
2. 宿主楼总表已含泵电，其楼内公摊先扣整只泵表：`楼内公摊 = 总表 − 分表合计 − 泵电`。若扣成负数（总表不足以覆盖泵电），阻断 `PUMP_EXCEEDS_COMMON`，避免照旧分摊把泵电收第二次。
3. 泵电按受益房间面积跨两栋分摊；房间账单 = 分表用量 + 楼内公摊分摊 + 泵电分摊。
4. 各楼仍拿实测总表对账到瓦时：
   - 宿主楼：`分表合计 + 楼内公摊 + 泵表电量 == 总表`；
   - 邻居楼：`分表合计 + 楼内公摊 == 总表`（其总表不含泵电，泵电只进受益房间账单）。
5. 两栋泵电账是一份联合结算，任一栋对不平（`PUMP_RECONCILE_GAP` 等）整体 `REJECT` 挂起，签发门关闭，两栋都不能签发。
6. 重跑同样的读数与接线记录得到同一 `run_key`，复用同一批次，不重复计费；接线或读数变化才产生新批次。
7. 签发证据 `pump` 段同时给出泵表电量（起码/止码/差值）和各楼实测总表电量、对账差额与房间账单。

接线记录字段：`pump_meter_id`、`pump_start`、`pump_end`、`host_building_id`、`beneficiary_rooms`。宿主楼或受益房间在读数数据中不存在、读数倒退、JSON 非法等都会进入问题清单并阻断联合结算。无接线文件的批次按“无共用泵”处理，沿用原公摊流程。
